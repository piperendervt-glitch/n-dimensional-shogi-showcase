## 3. 計画の要点

候補作業場所は `C:\dev\n-dimensional-shogi-showcase`。本線 `C:\dev\n-dimensional-shogi` は変更しません。

場面は、01：美しい通常盤の導入、02：高さへの逃走、03：3Dでの追撃、04：4D断面回転・w移動・帰還後の不在、05：4Dから攻めて終局、の5つです。

Aは歩優先の4D対応CPU、Bは3Dまでの部分観測CPUです。Bが見えない駒も、正本ルールには残ります。画面の可視性でCPU入力を決めません。

最初から固定4Dルールを使い、開始時だけ通常の2D将棋に見せる案を推奨します。途中の能力解禁やルール変更ではありません。

4D幾何は固定ソリッドと超平面の交差。フェードだけ、任意のhide、投影だけ、角度ごとのモデル交換では代用しません。

最初の小さな実証は「木製歩1枚＋盤の一部＋真の断面＋影」。それと、全応手を検証できるCPUシナリオを並行して組み立てる計画です。

## 4. 特に確認する独自ルール

次の点は元の要求を実装可能にするために提案したもので、まだ承認されていません。

| 項目 | 推奨案 | 意味 |
|---|---|---|
| 歩の移動 | 前進＋u/v/wへの1マス横断・捕獲 | 通常将棋の歩ではない |
| 終局 | 王捕獲。自玉安全による着手拒否なし | 標準の王手・詰み対局ではない |
| 成り・打ち | 初版はなし | 完全な本将棋モードではない |
| Bの観測 | 論理w=0の駒だけ | 不可視駒を正本から削除するのではない |
| 初期対局 | 見た目は標準風、実際は固定4Dデモ | 本線のN=2互換性とは別 |

このセットを変更する場合、特に歩の最終攻撃と、隠れた王手へのBの対応を再設計します。Codexが都合よく暗黙決定するものではありません。
