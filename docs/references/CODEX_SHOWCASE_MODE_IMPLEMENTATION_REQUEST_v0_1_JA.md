## 1. Goal

新しい別リポジトリに、**美しい屋外広場の卓上で、2D将棋に見える対局から3D逃走、4D回転、不在、4Dからの攻撃と終局へ進むWindows PCデモ**を制作してください。

主役は、ほぼ歩しか動かさないが4Dを使えるCPU。相手は、3Dまでは少し賢く追撃するが4Dの駒を認識・使用できないCPUです。

起動直後はメニューなし、人物なし。木製の卓・盤・駒、自然光、広場の奥行きが主役です。単色の箱が動く技術デモを、Showcaseの完成として提出しないでください。

4D回転は、固定4Dソリッドの真の3D断面変化で示してください。フェード、恣意的な非表示、角度ごとのモデル差替えを、その代わりにしないでください。

## 4. 採用する契約

以下はPLANの推奨案です。人間が承認したものだけ採用し、変更指示があれば差分を記録してください。

### 4.1 固定ルール

`showcase-asymmetric-4d-king-capture/0.1`、q=(f,u,v,w)、各軸−4…4、初期はv=w=0の通常風9×9・40駒配置。

開始からN=4、陣営能力・観測ポリシー・遮蔽方式を固定してください。Scene番号やカメラに応じてルールを書き換えないでください。

歩の前進＋非前方軸の横断、その他8種相当の未成駒の移動、成り・打ちなし、自玉安全による着手拒否なし、王捕獲終局はPLAN §6の提案です。標準将棋として宣伝・記録しないでください。N=2標準モードを変更しないでください。

本線のヘルダー飛車モデルを使う方針に合わせ、飛をH(1,1)、角をH(2,2)として実装してください。移動先述語と遮蔽方式は分けてください。格子直線と閉セルSupercoverの定義、例外となる跳躍・一歩はPLAN §6.5に従ってください。

遮蔽方式は開始前の設定／起動引数で選択でき、同一runでは変えられないようにしてください。完成シナリオの必須検証対象はlattice-line/1です。他方式で同じ台本が不成立でも、設定を戻して成功したように報告しないでください。

### 4.2 CPUと情報境界

A：歩優先、全4D観測、4D移動可能。

B：浅い探索、論理w=0の駒のみ観測、w方向への移動不可、v方向は使用可能。

Bの入力は専用Observationだけとし、全GameState、UnityのScene、Rendererの可視駒、全攻撃表、隠れたmove、全状態hashを渡さないでください。内部モデルも4Dを追跡するものにしないでください。

DirectorからBへの候補絞込みで隠れた情報を渡さないでください。Bが知らないw方向の敵位置を変えても、同じ観測・公開情報・seedなら同じ選択になることを試験してください。

RuleCoreには全駒を残してください。Bが観測できないことを理由に、占有・攻撃・捕獲・終局の計算から駒を除外しないでください。

### 4.3 CPU戦とリプレイ

既定のDirectedLiveでは、実際にCPUが毎手候補を評価し、シナリオの選好を反映して提案してください。固定seed・固定ノード予算を使い、同じ条件で再現できるようにしてください。

VerifiedReplayは、検証済みの棋譜を各手再検証する別モードです。台本の再生を「AIが自由対局して発見した勝利」と説明しないでください。途中の隠れたモード切替は禁止です。

正式な初期配置から全応手を含む着手列を作ってください。PLAN §7の終盤例は、局所的な成立条件の説明にすぎません。その例へ途中で駒をワープさせないでください。

### 4.4 4Dの真実性

PLAN §8のH=P+BξとS_iの交差から3D境界を生成してください。B^TB=I、B^Tn=0を保ち、観察断面・カメラの変更でGameStateを書き換えないでください。

基準は主役u=0、u–w回転、H0:w=0とH90:u=0です。盤中心と主役が残る条件、w移動中の交差、帰還後の不交差を正式形状で検証してください。

押し出し形Aを独立した幾何基準とし、承認されていればu/w対称形Cを外観比較してください。同じ4Dソリッドを通常時と回転時に使い、形状版を固定してください。

盤・駒のw寸法と、ゲームの着手領域を分けてください。物理衝突や見た目の厚みを将棋の遮蔽へ流用しないでください。

### 4.5 材質・影・反射

生成点に局所4D材質座標と面IDを持たせてください。新しい断面に木目UVや「歩」の文字を毎回都合よく貼り直さないでください。

Color/Depth/Normal/Shadow/Reflection等に同じSection版を使ってください。幾何的Emptyの駒の影・反射・履歴が残らないか確認してください。メインカメラ外であるだけの駒を、影・反射からも消さないでください。

Scene 04の帰還停止後はghostなし。補助の軌跡・残像は別レイヤーとし、実体ID、占有、影を増やさないでください。

consoleからCPU・観測・全着手を実行できるようにしてください。通常風の初期配置から、同じ歩が3Dへ逃げ、追撃され、4Dへ逃げ、攻撃して終局する棋譜を作ってください。

Scene guard、手番、捕獲、状態hash、Bの観測、seed、思考予算を記録してください。各手を独立検証し、シナリオ改ざんの破壊試験も行ってください。

Standaloneで1080pと1440p、通常・最悪角・消失直後・VFX最大、cold/warmと連続ループを測定してください。未達なら重い光学効果から調整し、幾何の意味を変えないでください。

Editorなしで起動できるWindows x64アプリ、操作手順、完全な試験対応表、記録、残件を提出してください。ビルドしただけでなく、実際に起動・再生・一時停止・終了を確認してください。実行できない環境ならBLOCKED_RUNTIMEとして明示し、成功を捏造しないでください。

## 6. 品質と性能の実装方針

初期構成はHDRPのラスタ描画、静的背景GI、動的断面へのプローブ照明、動的影、静的環境の反射プローブ、検証済みSSRを候補にしてください。APVをリアルタイムの完全GI再計算と説明しないでください。

GPU Compute、RT、独自BRDFは初版の必須ではありません。まずCPU断面の正しさとメッシュ更新費用を測定してください。毎フレームの大量Mesh生成・破棄、全マスGameObject化、毎フレームMeshCollider作成を避けてください。

予算内でTAA/DLSSの動的トポロジー対応が成立しなければ、SMAA等の基準を残してください。フレーム生成を使った表示fpsを、実描画の達成として数えないでください。

性能値はCPU・GPU・待機、median/p95/p99/最悪、GC、VRAM、出力・内部解像度、quality/AA/driverを保存してください。Editorの値をStandaloneの値として報告しないでください。

## 7. 自動試験と独立検証

PLAN §12の**SM-AC-01〜SM-AC-48をすべて対応表に載せてください。** 番号を削除したり、失敗する期待値を実装に合わせて緩めたりしないでください。

最低限必要な独立検証：

1. 幾何：主方式と異なる計算経路で半空間の既知解・交差頂点・閉曲面を照合。
2. ルール：棋譜の前後局面・駒種・移動・占有・手番・終局を別の簡潔な検証器で照合。同じIsLegalMoveの呼出しだけを独立検証と呼ばない。
3. 観測：同じB観測となる反事実局面、Renderer変更、隠れた情報注入を検査。
4. 描画：GeometryReferenceとShowcaseRasterを同じ断面系列で比較し、色だけでなく影・深度・反射を確認。
5. 配布：Windows実行物、README、記録のcommit・build・runの対応を確認。

破壊試験では、隠れた状態をBへ渡す、非合法手を棋譜へ挿入する、実体の片方の描画パスだけ旧断面にする、といった故障を検出できることを示してください。製品へ故障が残らないよう分離してください。

人間の感性が必要な「美しい」「分かりやすい」「大部分が消える」を、自動の数値スコアで勝手にPASSにしないでください。

## 9. 継続・停止の基準

承認された範囲内の実装、修正、試験、回帰はまとめて継続してください。小さなメソッド名や照明値の判断のたびに人間へ確認を求める必要はありません。

以下は勝手に越えず、理由と影響を報告してください。

- 重要なルール・CPU観測・4D形状の意味を変更しないと進まない。
- 本線や別の作業実体へ書込みが必要になる。
- 有料素材・API、追加取得権限、管理者操作、外部公開が必要になる。
- 参考画像または実行環境がなく、その確認だけが実施できない。
- シナリオ成立のために不正手・局面置換・不可視情報のBへの漏えいが必要になる。

一つの障害があっても、独立した許可済み作業がある場合はそちらを進めてください。障害の範囲、進めた範囲、未完部分を分けて提出してください。

## 10. 最終報告の形式

最初に `ACCEPTED / TECHNICAL_PASS + HUMAN_PENDING / PARTIAL / BLOCKED` のいずれかを、証拠に基づいて示してください。人間承認がなければACCEPTEDとはしないでください。

続いて、実作業パス・branch/HEAD・未commit状態、実行物、全試験対応表、5場面の成立状況、真の断面の証拠、CPU情報境界の証拠、画像／動画、性能、素材、残件を報告してください。

別run、本線のM0/V0、模擬表示、パストレース静止画を、このShowcase実行物の合格証拠に流用しないでください。

本依頼の目的は、**美しい見せ場と、偽装しない4D幾何を両立すること**です。どちらかを落とした場合は、正直に部分提出として残してください。
