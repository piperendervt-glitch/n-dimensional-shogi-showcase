## 作業と採用仕様

実装先は `C:\dev\n-dimensional-shogi-showcase`。ユーザーの明示回答を [承認記録](APPROVALS.md) に記載した。ローカル `main` は未commitで、HEADはまだ存在しない。本線 `C:\dev\n-dimensional-shogi` へ書き込んでいない。指定remoteを登録して読取り確認したが、commit・push・公開は行っていない。

Unity 6000.3.11f1 / HDRP 17.3.0、Windows x64、Mono、Direct3D 11のStandaloneを制作した。ルール・CPUと幾何はUnityから独立したC#パッケージとし、Unity側が局面・断面メッシュ・演出を接続する。

開始から固定4Dの独自ルール `showcase-asymmetric-4d-king-capture/0.1` を使用する。歩の非前方軸横断と捕獲、成り・打ちなし、王捕獲終局を採用した。標準将棋互換とはしていない。Aは全4Dの情報を持ち、Bは論理w=0だけを見る専用3Dモデルで探索する。既定の格子直線遮蔽と閉セルSupercoverは別runとして固定され、未知方式を拒否する。

DirectedLiveは毎手の候補評価と固定ノード予算を実行する。演出に合わせる強い選好を明示的に含むため、「自由対局でAIが発見した勝利」とは説明しない。Aの14手は全て主役の歩、非歩救済は0回。Bは銀・金・飛車・歩で応答し、観測にない4D駒の位置を参照しない。VerifiedReplayは同梱棋譜を開始前・各手で検証する別モードで、途中切替はない。格子直線の棋譜hashは `8aeb2a56571719a6b1ea74424da8279a44864edd25c3d766a6680800d991f466`。

ShowcaseRasterでは4Dへ入る前から画面全体を寒色・減彩へ変え、圧力波と周縁の歪みを加える。最初の回転は10秒、以降の出入りは7.5秒を基本とする。速度は滑らかに増減し、抵抗を受けるように進む。現在フレームのみを用いる効果で、過去画像・偽の駒・深度への書込みはない。Tで切替でき、GeometryReferenceでは無効。一時停止では回転角、効果強度、位相、木漏れ日の動きも止まる。

## 真の断面と材質

固定4D半空間ソリッドと観察超平面 `H=P+Bξ` の交差から境界メッシュを生成する。断面・カメラ変更はGameStateへ書き戻さない。Aは数学基準の押し出し形、Cは固定u/w対称形で、角度に応じたモデル差替えはない。各駒は1つのMeshを更新し、Emptyでは三角形を除く。全マスGameObjectやMeshColliderは作らない。

頂点には局所4D位置と面IDを保持する。A材質は `M3(f,u,v)`、C材質は固定アフィン場 `M3(f,u+w,v)`。漢字は元ソリッドのTop面だけに存在し、角度・カメラによる貼り直しはしない。数学上の整合と、木目・文字の見え方に関する人間判断は別に扱う。

## 画質・性能・素材

形状は手続き生成。CC0のPoly Haven実写木材2種と砂岩1種を採用し、2048pxの木目・石材・法線・粗さ・AOを使用する。盤の筋と駒の文字には微細な彫り法線を持たせ、黒字を太くした。天板にはクリアコートと毎フレームの平面反射を使用する。文字の凹凸は法線によるもので、実変位やパララックスとは呼ばない。完成した駒名画像に導入済みYu Minchoを使用し、フォント本体・汎用文字アトラスは配布しない。人物・開始メニュー・購入素材・生成画像サービスはない。[素材台帳](ASSET_REGISTER.md) と原本12マップ・加工40画像のhashを保存した。

物理大気の空とIBL、固定露出とACES、Bloom、樹木と木漏れ日cookie、PCSS、非時間蓄積SSAO、接地影を実装した。暖色の回り込みには補助面光源も用いており、焼き込みライトマップやSSGIによる完全な間接光ではない。F2〜F8と修飾キーで各効果を切り替え、実AO／接地影バッファを表示できる。[照明設計と操作](LIGHTING_V2_JA.md) に設定と制限を記録した。

追加指示に従い描画目標を30fpsへ変更した。性能はStandaloneの実フレームを記録し、撮影run・操作run・clean benchmarkを分ける。CPU/GPU、待機、分位点、GC、メモリ、可視IDを保持し、フレーム生成は無効。記録用AVIは実画像の時刻を15fpsへ標本化した閲覧用動画で、ゲーム描画fpsの測定値ではない。

最終の性能値、実行物と画像・動画の対応、残件は最終検証後に本書末尾へ追記する。

予備計測では0〜2°付近で40駒の断面更新がCPUのボトルネックとなった。描画品質や形状を変えず、変更された断面の純粋C#計算を最大8ワーカーへ分配した。全結果をjoinしてからメインスレッドでUnity Meshを更新し、各描画パスが未完了の計算結果を参照しない。少数（3件以下）の更新は直列とし、同じ座標・角度は既存メッシュを再利用する。予備計測は旧buildの記録として保存し、最終性能の合格証拠には含めない。
