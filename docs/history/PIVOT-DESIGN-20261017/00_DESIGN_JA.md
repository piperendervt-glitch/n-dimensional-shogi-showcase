## 2 座標と実体のモデル

### 論理座標と空間配置

既存Coreの順序は `(F,U,V,W)`。対応は `X=U, Y=V, Z=F`。盤域、前方、G/PはCoreの整数座標Q4で計算する。高さhを論理Vや盤域へ加算しない。

表示用の固定埋込を、Core順で `E=(0,0,h,0)` とする。切断に渡す実体位置は `q_world=q_core+E`。初期の `V=W=0` は世界の `Y=h,W=0` になる。逆変換は `q_core=q_world−E`。hは表示配置であって製品ルールではない。

セル、駒の4D凸形状、選択枠、G/P・攻撃候補はすべて同じEを使う。既存の `ShapeFactory` と半空間切断器を再利用し、木駒を丸ごと近傍投影して切断の代わりにしない。図の点は駒の参照位置であり、実装では駒の有限な形状全体を切断する。

### 操作中心と超平面

`C` は表示座標枠の原点、有限表示窓の中心、4D回転の基準点を兼ねる。無限超平面自体に固有の中心があるとは扱わない。

`B=(b1,b2,b3)` を直交基底、`n` を単位法線として、超平面は `H={q | n·(q−C)=0}`。切断内の局所座標は `u=Bᵀ(q−C)`。実切断と窓のクリップを先に行い、この局所座標を3Dに表示する。断面外を投影して表示しない。

4D回転Rでは `B'=RB, n'=Rn`、CとEは不変。中心移動では `C'=C+δ`、BとnとEは不変。論理局面・手番・G/P集合はどちらでも不変。

### 3D表示位置とクリック

既存切断器の局所3軸は、Unityへ `T(u1,u2,u3)=(u2,u3,u1)` で渡す。長さは既存の `s=0.05 m/セル` を使う。3D表示の基点Aを独立に保持し、全メッシュとpickは `p3=A+sT(u)` を共有する。

初期XYZでは、木盤の基準点 `A_O=(0,0.86,0) m`、`C=P`、`A=A_O+(0,s·h,0)` とする。A_Oとsは実在する `SectionView.Anchor/Cell` を参照する。旧 `AirAnchor=(0,1.1,0)` を別経路で併用しない。

中心をδだけ移す際は、移動前のBを用いて `A'=A+sT(Bᵀδ)` とする。これにより、超平面内の移動で変わるのは表示窓と中心であり、共通領域の駒が不必要に跳ばない。法線方向の移動ではAは動かず、切断集合が変わる。XYZでPからOへ戻すとAもA_Oへ移り、駒は高さhを保つ。

4D回転中はAを固定する。Cの表示位置をピボットとして実断面の向きと形が変わる。Aはカメラpanではなく断面表示枠の状態であり、C・Bと一緒に保存する。W移動を常にUnityの下方向へ置き換えない。一般姿勢では、4Dの原点移動が画面上の上下移動になるとは限らない。

木盤は初期XYZでOを示す静止した背景の台とする。回転後の断面座標の投影像と、この背景台を二つの4D実体として混同しない。O/Pの説明用マーカーを製品プレイ画面へ常設追加しない。必要な状態は小窓の軸と断面位置、および検証用記録で確認する。

カメラは独立したyaw/pitch/distance/panを持つ。断面変更、候補更新、選択変更で自動的にカメラを初期化しない。既存の手番カメラ演出がある場合は、手動操作後に勝手に上書きしないよう、入力中・手動操作済み状態を明示的に扱う。

## 3 基準断面と小窓

以下はCore順の基底と法線。`eF/eU/eV/eW` はCore単位軸。符号は既存 `SliceAxes` と整合する。

| 選択軸 | ビュー | Unity表示の軸順 | 切断器の基底 b1,b2,b3 | 法線 |
|---|---|---|---|---|
| W | XYZ | X,Y,Z | eF,eU,eV | eW |
| Z | XYW | X,Y,W | eW,eU,eV | −eF |
| Y | XZW | X,W,Z | eF,eU,eW | −eV |
| X | YZW | W,Y,Z | eF,eW,eV | −eU |

基準へ切り替える操作はCとAを保持する。Wは向きだけXYZへ戻す操作であり、原点移動や局面リセットではない。中間姿勢をそのまま切断し、向きが一般姿勢ならXYZ等の基準名と偽表示しない。

プレイ画面の4小窓は、それぞれCを通る基準3空間S_iと、現在のHとの交差を示す。基準空間をO固定へ勝手に戻さない。`S_i=C+E_i ξ` なら交差は `(E_iᵀn)·ξ=0`。係数がゼロなら3空間全体と一致するので立体範囲として示し、通常は2次元の交差面を表示する。4枚に同じ青い板を貼らない。

| 基準小窓 | 初期 C=P | 原点移動後 C=O |
|---|---|---|
| XYZ | W=0 | W=0 |
| XYW | Z=0 | Z=0 |
| XZW | Y=h | Y=0 |
| YZW | X=0 | X=0 |

一般の移動後は省略軸の実座標を表示する。hという文字列の固定表示ではなく、保存されたCから計算する。小窓の境界、交差形、軸は同じ状態版を使う。

プレイの4小窓は承認画像の軸操作UIとして、現在のH、有限表示範囲、世界軸を表示する。木駒の複製と駒数ラベルは置かない。中央を強調する場合は操作中心Cのマーカーであり、選択駒の絵にしない。したがって現行miniの中心点一致判定による駒表示を温存しない。駒の実断面は主表示、設定の駒と候補は2D図で確認する。

小窓の参照表示箱はC中心の半幅4.5。その中で、Hとの交差に主表示窓の6不等式 `|b_j·(q−C)|≤HalfWindow` も適用する。一致時はこの有限な3次元範囲を立体として描き、一般時はクリップ後の交差面を描く。参照箱と実交差の輪郭を色と不透明度で分ける。主窓の向きが変わっても固定の青い立方体へ置き換えない。

過去に作成した8図は「Oを通る固定基準空間」の説明図であり、今回の製品小窓は「Cを通る基準空間」である。この違いを明記し、旧8図の件数や切断を製品小窓へそのままコピーしない。

### 機能するXYZWギズモ

主軸の表示は、世界軸e_iの接成分 `Bᵀe_i` をTと現在の3Dカメラ回転で画面へ写して計算する。法線成分は `n·e_i`。カメラを回しただけでも、主軸と4小窓の三軸が更新される。固定Quaternionや固定端点の絵で代用しない。

初期XYZでWは法線なので、接成分の射影はゼロになる。この場合はゼロ長矢印を別方向へ偽装せず、ギズモ中央の法線記号とWラベルで選択可能にする。正負は奥・手前の記号として区別する。これは既存ギズモ内の表現であり、新しいメニューや操作パネルではない。

各小窓の三軸はその基準空間の表示スロットと同一のカメラ姿勢から描く。描画した軸端点と、ドラッグ量を算出する端点は同じ計算結果を使う。画面へほぼ射影されない軸はドラッグを開始せず、他の小窓から同じ世界軸を操作できる。クリックによる断面選択は退化軸でも可能。

## 4 回転と入力

マウス／キーボードで操作し、プレイ画面に回転平面・角度・位置移動ボタンを増設しない。入力開始時に所有者と基準状態を保存し、途中でフォーム・盤・軸・カメラへ所有を渡さない。

| 入力 | 動作 |
|---|---|
| 主表示の左クリック | 現断面の駒／候補を選択。ドラッグになったら着手しない |
| 主表示の左ドラッグ | 3Dカメラを回転。既存右ドラッグ回転も互換として維持 |
| 中ドラッグ、またはShift＋左ドラッグ | カメラpan |
| ホイール | カメラzoom |
| Ctrl＋左ドラッグ | 横移動でXW、縦移動でYWの4D回転 |
| Ctrl＋Shift＋左ドラッグ | 横移動でZW、縦移動でYWの4D回転 |
| 主ギズモの軸クリック | 上表の基準断面へ連続遷移。CとAを保持 |
| プレイ小窓の世界軸ドラッグ | Cと表示窓を同じ世界4D軸に沿って移動 |
| 小窓にポインターがあるときHome | CをOへ移動。B・カメラ・局面を維持 |
| 小窓にポインターがあるときShift＋Home | Cを開始位置Pへ移動。原点移動と区別する |
| Escape、フォーカス喪失 | 未確定ドラッグを開始状態へ戻す。別操作を確定しない |

Home系はフォーム入力中に実行しない。プレイ画面の既存ガイド領域と、設定の表示・操作カテゴリで操作説明を示し、追加の常設ボタンを作らない。Ctrl＋Z/Yの既存Undo/Redoと競合させない。

連続回転はUI軸のR_XW、R_YW、R_ZWで基底・法線を同時に回す。CoreではそれぞれU-W、V-W、F-Wであり、`Vec4.X=F` とUIのXを取り違えない。ドラッグ開始姿勢F0と開始ポインターを保持し、毎回の総変位から `F=R_YW(kΔy) R_XW(kΔx) F0` を計算する。Ctrl＋ShiftではXWをZWに置き換える。イベントごとの増分を逐次合成しない。これにより同じ開始点・終了点が、入力イベント分割数によって別の姿勢になるのを防ぐ。

主表示の修飾キー優先順位は `Ctrl＋Shift → Ctrl → Shift → 通常` とし、開始時に所有を固定する。向きと速度を反対側の窓ごとに変えない。一般姿勢から基準へ戻す場合もSO(4)の姿勢として連続補間し、3Dカメラだけ回して代用しない。

実装経路は、4D正規直交行列を決定的に平面回転へ分解し、各Givens回転を連続適用する方法を第一候補とする。別の同等なSO(4)補間を採る場合は、直交性・符号・終点・180度近傍を試験し、実装選択として記録する。要素ごとの線形補間で直交性を壊さない。

同一安定目標の再選択は無操作。遷移中の別クリックは最新1件を予約する。直接ドラッグで遷移を引き継ぐ場合は、その時点の連続姿勢から開始し、以前の予約を取消す。入力取消でC/B/A/カメラを一括復元し、古いpickを無効にする。

主表示を覆う装飾Panelや文字はraycast対象にしない。実ボタン・フォーム・小窓は所有領域を持ち、背後へのクリックを止める。Canvas全面を入力遮断用の透明Panelにしない。

## 6 保存と再読込

新しい表示保存は、埋込方式の版、h、C4、基底と法線16、表示基点A3、有限窓寸法、カメラ、選択・平面表示の基準を含む。Q4、ルールハッシュ、MatchSnapshotへhを混ぜない。一般角度を4基準へ丸めて保存しない。

既存 `SettingsStore` のview/1はcenter4/basis16/camera6だけを厳密に読み、未知属性を拒否する。その定義を黙って拡張しない。新しい表示schemaを持つ新規保存形式／新規パスを設ける。既存設定・旧対局・棋譜・原本は保全する。

実装は、論理設定と新表示状態を一つの版付きbundleとして同一ボリュームで一時保存・再検証・置換する方式、または世代別ファイルと最後に確定するmanifestで一括コミットする方式を採れる。片方だけ成功した状態を「保存完了」と表示しない。対応する設定内容のhashを検証して、別局面へ表示状態を誤接続しない。

旧表示schemaにはEとAがない。旧設定の論理内容を変更せず読めるようにし、旧表示を新しい初期表示へ移す場合は「表示設定を新方式の初期状態にした」と明示する。未知データの推測修復、旧ファイルの上書き、失敗時に現在の編集を破棄する処理は禁止する。明示的に移行できる既知形式以外は理由付き拒否とする。

新表示読込は有限性、直交性、正の向き、範囲、既知方式を検証してから一括反映する。新しいC/A/カメラを一部だけ採用しない。任意角、中心移動後、原点復帰後のそれぞれで再起動往復を試験する。

| h | **3.0セル**。既存単位で0.15m。C=PとC=Oの両方で初期木駒が半幅4.5の窓に収まり、原点移動だけによる消失を避ける。旧0.86m/1.1m差からの逆算ではない |
| 対局の有限窓 | 各局所軸半幅4.5セル。初期9×9配置を含む。窓外は実クリップする |
| 設定の有限窓 | 原点移動の認識確認を含めるため初回は同じ半幅4.5。選択周辺だけを拡大する場合はカメラzoomで行い、勝手にCを変更しない |
| 主表示左ドラッグ閾値 | 6 Canvas基準px。閾値を超えた入力のpointer-upは着手に使わない |
| カメラ回転感度 | 横0.25°/px、縦0.20°/pxを開始値にし、解像度とCanvas倍率を補正 |
| 4D回転感度 | 0.25°/Canvas基準px。大きな入力を補間する場合も開始姿勢と総変位の同じ経路上で評価し、終点を変えない |
| 軸移動 | 32 Canvas基準px/セルを開始値。開始時の射影方向・尺度を固定。見かけ長6px未満は開始拒否 |
| 90度遷移 | 0.45秒を開始値。途中の正確な断面と全小窓を同期 |
| 数値誤差 | 既存幾何許容を継承。表示状態の直交誤差1e-6以内。状態再正規化はドリフト対策のみ、意図した角度を基準へ丸めない |

特にh=4.5・半幅4.5は採用しない。原点復帰時に駒の基部が窓の上端になり、実体がクリップされるためである。hを調整したら `h + 木駒の最大高さ < 対応する窓の半幅` を初期XYZの原点移動試験で確認する。他の姿勢・大きな移動で断面や窓から駒が消えることは実際の幾何として扱う。
