# CFG2 承認画像と実装対応・実画面前の監査

状態: STATIC_REVIEW_ONLY。画像3点を実ピクセルで閲覧し、2026-10-17のCFG2コードを読み取り照合した。Windowsスクリーンショットによる合格ではない。コード編集は親担当のrevision-01ビルド開始通知後に停止した。

## UI-01 初期メニュー

対応: `Cfg2App.Ui.CreateMenu` は金色大タイトル、英語副題、左の5行（PvP/PvC/CvC/オプション/終了）、暗い半透明パネルと青い初期選択を持つ。背景は既存の実3D広場。メニュー用の王・飛・角を実木素材で生成する。画像そのものを背景に用いていない。

差異・確認待ち: 参照の筆文字タイトル、人物・モニター・歯車ピクト、縁の発光、装飾章は再現していない。文字の短い記号表現と既存フォントを使う。参照の階段状木盤は現コードの既存木盤と空中表示へ置換されており、木の質感と構図の近さは実画像で確認が必要。5項目は機能コードへ直接接続しているが、このレビューは操作試験を代替しない。

## UI-02 対局

対応: 盤・40駒・捕獲側台は実局面のデータから描画。元の木盤の上に固定XYZ/W=0実断面の木駒を置き、別の空中断面は現在SliceFrameから正確に切断する。捕獲台はA/Bの固定world位置と捕獲側所有で生成し、王は通常台へ入れない。時計2個は上下、メニューは右上、主XYZWとXYZ/XYW/XZW/YZW小窓を右に配置。4小窓は現在断面との関係と、固定軸条件に一致する実駒中心を表示する。木材・表面テクスチャは既存ローカル資産。

差異・確認待ち: 参照の曲線・光輪ギズモは直線の軸ハンドルで簡略化。4小窓内の木駒アイコンは小さいため、初期40駒時の密度と軸文字の可読性を実画像で確認する。9マス幅の空中グリッドは断面729セル相当になる姿勢がある。三角形対角線除去・共通辺重複除去と淡色化は実装済みだが、透過積層で盤・駒を隠さないか要確認。物理板と空中の両方に同一の駒が見える構成であるため、二つの表示の区別と誤認しにくさも実画像で判断する。

台は1種1木駒＋実個数で集約する。最大7種の2行配置が台からはみ出さない寸法にしている。数文字はカメラに向くTextMeshのため、HDRPでの文字色・材質表示はPlayerで確認が必要。PvPのカメラが180度移っても台所有は変わらない。

## UI-03 駒設定

対応: 1536×1024基準で左6カテゴリ196px、木駒一覧186px、中央730px、右詳細380px。金色ヘッダー・青選択・半透明暗パネル、基本/詳細/表示タブ、下部試し配置と表示オプション、常設保存群なし。右詳細のみ独立ScrollRect。2DタブはXY/XZ/XW/YZの固定2軸図で、選択Q4の他2座標を条件ラベルに表示して非一致の駒を除外する。候補青・攻撃赤・選択金は実G/P/攻撃集合から描く。

差異・確認待ち: 参照画像では中央右に4つの2D図が同時表示されるが、実装は既存4超平面を右に維持し、上の2Dタブで中央の大きい確認図を切り替える。これは2D図が4超平面を置換しない契約との両立を優先した配置。成駒一覧は無効説明に整理した。小さい木駒一覧の文字、詳細タブ幅115px、1280×720の縮小時に日本語が欠けないか実画像が必要。

## 入力上の先行指摘（親担当へ送付済み）

1. `PreviewDown` のrollback開始値を入力所有取得前に共有fieldへ代入していると、別pointerの拒否Downが既存ドラッグの取消値を上書きし得る。親担当が修正する。
2. 2D図の呼出側がInputOwnershipを渡していない版では、他の入力との排他が接続されない。さらにslice revisionだけを描画revisionに用い、callbackへ現在preview.Revisionを渡す構成では、Down/Up間の試し盤・Draft変更を見落とせる。revision-01後にstate/draft getterをPlane初期化へ追加してDown/Up照合する案を共有した。この経路を未検証のままC2-10 PASSにしない。
3. Mini/PlaneのInitialize再呼出による旧子UI重複は、旧子を即非表示→Destroyして再構築する冪等初期化へ修正済み。

追記: revision-01はC# import前の環境停止となり、親担当の再編集指示で2のgetter補強を実装した。`Cfg2PlaneView.Initialize(...,ownership,stateRevision,draftRevision)` の追加optional引数をDown/Upで照合する。描画Refresh世代も照合し、拒否数を`RejectedStaleCount`で実Player試験から検証できる。親担当は呼出2箇所を接続する。`logs/cfg2-check-settings-03.log` は型検査exit0。stale拒否の実入力試験PASSは別途Smoke証拠を要する。
